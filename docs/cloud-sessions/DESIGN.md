# Cloud sessions 運用設計書（taro リポジトリ）

作成日: 2026-09-27
対象: shenyexiaoti-gif/taro
実装担当: Sonnet（本書の「実装タスク」節をそのまま渡す）

## 0. この設計のゴール

期間限定クレジットを「無料枠」で終わらせず、クレジット切れ後も残る任せ方の型を作る。
成果物は3つだけに絞る。

1. リポジトリを Cloud sessions が迷わず動ける状態にする（CLAUDE.md・起動フック・依頼テンプレ）
2. 時間帯ごとの「渡してよい仕事」の判定表
3. 消費ログ。どの型が何ドルで何を返したかを記録し、期限後の継続判断に使う

## 1. 前提と未確認事項

記事の記載内容であり、本書作成時点で俺は一次確認していない。運用開始前に受取画面で確認する。

| 項目 | 記事の記載 | 確認方法 |
|---|---|---|
| 付与額 | Pro 100ドル / Max 250ドル（一回限り） | 受取画面 |
| 受取期限 | 日本時間 2026-10-08 15:59 | 受取画面 |
| 利用期限 | 日本時間 2026-11-05 16:59（固定） | 受取画面 |
| 用途 | Cloud sessions のみ | 公式ブログ |
| 受取方法 | CLI で /claim-credit、または Code 画面の導線 | 実行して確認 |

受取は今週中に済ませる。後で受け取っても利用日数は増えない。

## 2. このリポジトリの現状と相性

現状は x-mcp-oauth/ のみ。標準ライブラリだけの Python スクリプト2本と README。

| 作業 | クラウド向き | 理由 |
|---|---|---|
| スクリプトの構文・静的チェック、単体テスト追加 | 向く | 外部依存なし、差分とテストで判定できる |
| README と実装の突き合わせ | 向く | 判断の危険が小さい |
| x_oauth2_pkce_check.py の認可フロー実走 | 向かない | X の承認画面、ローカルの callback、本物の秘密が要る |
| local_env_report.py の実走 | 向かない | 手元マシンの設定を読む道具。クラウドで回す意味がない |

鉄則: .env と実トークンはクラウドに置かない。環境の Secrets にも入れない。実走は手元でやる。

## 3. 時間帯別の運用ルール

記事の提案10個を、このリポジトリで実際に回す5枠に圧縮する。

| 枠 | いつ | 渡す仕事 | 渡さない仕事 | 戻り先 |
|---|---|---|---|---|
| A 退勤前 | 退勤30分前 | 再現条件がある不具合、テスト追加 | 仕様変更を伴うもの | 朝に PR を見る |
| B 移動中 | 通勤・移動 | 調査と切り分け。コード変更なし | 実装 | 到着後にレポートを見る |
| C 就寝前 | 寝る前 | 機械的に正誤が出る一工程 | 範囲の広い実装 | 朝に PR とテスト結果 |
| D 外出・出張 | 半日以上 | 修正・テスト・説明の3点セット | 外部認証が要るもの | スマホで PR 確認 |
| E 手元作業中 | PC 前 | 並列化の分解案だけ作らせる | 同一ファイルの同時修正 | 分解案を見て別セッションへ |

同時実行は最大2本。同じファイルを触る依頼は並列にしない。

## 4. 依頼テンプレート（全枠共通）

全依頼をこの7項目で書く。空欄が埋まらない仕事は、まだクラウドに渡す段階ではない。

```
目的：
対象範囲：
完了条件：
変更してはいけないもの：
実行するテスト：
判断が必要になったときの停止条件：
最後に報告してほしい項目：
```

停止条件の固定文（全依頼の末尾に必ず付ける）:

```
仕様判断、外部サービスへのログイン、秘密情報、破壊的操作が必要になったら、迂回せずその時点で止め、状態と必要な操作を報告すること。
```

報告項目の固定文:

```
変更の目的、主要な差分、実行したテスト、確認してほしい判断点、元に戻す場合の範囲、未解決点。
```

## 5. リポジトリに追加するもの

```
taro/
├── CLAUDE.md                          クラウド側の行動規約（新規）
├── .claude/
│   ├── settings.json                  SessionStart フック登録（新規）
│   ├── hooks/session-start.sh         構文チェックの下準備（新規）
│   └── tasks/                         枠ごとの依頼テンプレ（新規）
│       ├── A-before-leaving.md
│       ├── B-commute-investigate.md
│       ├── C-bedtime-one-step.md
│       ├── D-away-fix-test-explain.md
│       └── E-split-plan.md
├── x-mcp-oauth/
│   └── tests/                         単体テスト（新規、標準 unittest）
└── docs/cloud-sessions/
    ├── DESIGN.md                      本書
    └── usage-log.md                   消費ログ（新規）
```

### 5-1. CLAUDE.md に書く規約

- 作業は必ず指定ブランチで行い、main へ直接 push しない
- .env、トークン、Client Secret を生成・コミット・出力しない。伏字で扱う
- X API への実通信を行わない（テストはモックで行う）
- 依存を追加しない。標準ライブラリのみの方針を守る
- テストは `python3 -m unittest discover -s x-mcp-oauth/tests` で回す
- 1 PR は 1 目的。無関係な整形を混ぜない
- 報告は第4節の報告項目の形式で PR 本文に書く

### 5-2. SessionStart フック

- `python3 -m py_compile x-mcp-oauth/*.py` を走らせ、構文エラーを最初に表面化させる
- 失敗してもセッションは止めず、警告として出す
- ネットワークアクセスはしない

### 5-3. テスト方針（x-mcp-oauth/tests）

実通信なしで検証できる純粋関数だけを対象にする。

- PKCE: code_verifier の長さ・文字種、S256 の code_challenge が RFC 7636 の例と一致するか
- 認可 URL: scope がスペース区切りになっているか、redirect_uri のエンコード
- 設定チェック: 末尾スラッシュ、http/https、カンマ区切り scope を検出できるか
- 伏字: 秘密の値がレポートに生で出ないか（local_env_report.py のマスク関数）

関数が分離されていなければ、振る舞いを変えない範囲で切り出す。切り出しが大きくなる場合は止めて報告。

### 5-4. 消費ログ（usage-log.md）

1依頼1行。期限後に「どの枠を続けるか」を決める材料にする。

| 日付 | 枠 | 依頼要約 | 所要時間 | 消費額 | 結果（採用/修正して採用/破棄） | 手直し時間 |
|---|---|---|---|---|---|---|

消費額は Code 画面の表示から転記する。取れない場合は空欄にし、推測値を書かない。

## 6. 予算配分（Pro 100ドル想定）

| 期間 | 使い方 | 目安 |
|---|---|---|
| 第1週（〜10/4） | 基盤整備（第7節の T1〜T4）と枠 B・C の試行 | 25% |
| 第2〜3週 | 枠 A・C・D を毎日1本 | 50% |
| 第4週（〜11/5） | 並列（枠 E）の検証、消費ログの集計 | 20% |
| 予備 | 失敗のやり直し | 5% |

Max の場合は同じ比率で 250ドルに拡大し、第2〜3週を他リポジトリにも広げる。
比率は目安であり、実消費の単価が見えた第1週末に見直す。

## 7. 実装タスク（Sonnet に渡す順番）

各タスクは独立 PR。上から順に実施し、前のタスクがマージされてから次へ。

| ID | 内容 | 完了条件 |
|---|---|---|
| T1 | CLAUDE.md 作成（5-1 の規約） | ファイルが存在し、規約7項目を含む |
| T2 | SessionStart フック（5-2） | 新規セッションで py_compile が走り、失敗時も継続する |
| T3 | x-mcp-oauth/tests 追加（5-3） | unittest が全件通る。本体の振る舞い変更なし |
| T4 | .claude/tasks/ の5テンプレ（第3・4節から生成） | 各ファイルが7項目＋固定停止文＋固定報告文を持つ |
| T5 | docs/cloud-sessions/usage-log.md 作成 | 表ヘッダのみの空ログ |
| T6 | README にクラウド運用の注意（実走は手元のみ）を追記 | 既存記述を変えず、節を1つ追加 |

T3 のみ本体コードに触れる可能性がある。その場合も公開された CLI の引数と出力形式は変えない。

## 8. 最初の1件（運用開始日にやること）

1. /claim-credit で受け取り、受取画面で第1節の表を確認して埋める
2. 枠 C で T1 を渡す（CLAUDE.md は機械的に完了判定できる）
3. PC を閉じる
4. 翌朝、PR を読み、消費ログに1行書く

見るのは「止まらなかったか」ではない。自分がいない時間を使って、レビューできる形で戻ってきたか。そこだけ。

## 9. やらないこと

- クレジットを使い切ること自体を目標にしない
- 実トークンを使う認可フローのクラウド実走
- 並列数を増やして速さを競うこと
- 通常のプラン枠に切り替わった後の自動継続（期限後は消費ログを見て判断）
