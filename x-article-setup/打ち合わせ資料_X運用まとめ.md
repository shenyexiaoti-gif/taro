## 2. なぜ「X MCPの運用マニュアル化」が完成しなかったか

マニュアルを作るには、実際に動いているMCPのツール一覧（ツール名・引数・何を叩いているか）が要る。
ところが、これを見る手段が3重に塞がれていた。

| 塞がっている場所 | 内容 |
|---|---|
| ① このクラウド作業環境 | X MCPサーバーが接続されていない。ツール一覧を検索しても0件 |
| ② ネットワーク | x.com・docs.x.com への通信がこの環境から遮断されている（403） |
| ③ 実行権限 | あなたのWindows PC上のファイル（`register_x_app.ps1`、`X_MCP_Windows`フォルダの中身）は、このクラウド環境から一切参照・実行できない |

このため、マニュアルの「土台」を、実物のMCPツール一覧からではなく、**X公式APIの仕様書と開発者コミュニティの記述**から組み立てる形になった。中身自体は正確だが、「あなたの手元のMCPが実際に何を持っているか」の一次確認ではない、という限界がある。

## 3. 完成したもの｜X記事ワークフロー Windows運用マニュアル（要約）

前回までに作って、ブランチ `claude/serene-faraday-hc5ai6` に置いてあるもの。

| ファイル | 何をするか | 使うタイミング |
|---|---|---|
| `setup_check.ps1` | 実行制限／PYTHONUTF8／Pythonの空箱／xurl本体／PATHを一括点検。`-Fix` で自動修正も可 | 導入時、詰まった時 |
| `check_hook.py` | check_hook.sh のPython版。記事保存時に自動で `--check` を走らせる | 導入時に1回登録 |
| `settings.local.json.example` | 上のフック登録の設定例 | 同上 |
| `CLAUDE_md_追記.md` | ネタ出しの主軸ズレ／作業内容の保存忘れを防ぐ2項目 | CLAUDE.mdに貼るだけ |
| `user必須化_貼り付け文.md` | `--user` 省略で別アカウントに誤投入する事故の防止 | 手元のClaude Codeに貼るだけ |

**運用の流れ（現状動いている範囲）**

```
「自動で3本書いて」
   ↓
ネタ選定 → 重複チェック → Web検索でファクト検証（主張台帳作成）
   ↓
執筆 → サブエージェントで事実検証 → 読者検品 → 日本語推敲
   ↓
サムネ生成（gpt-image-2）
   ↓
post_article.py（xurl経由）→ X記事の下書きへ投入
   ↓
ネタ帳に✅済マーク
```

ここは前回の打ち合わせの対象外（X記事は既に動いている）だが、Windows導入の詰まりを潰した分として記載。

## 4. できなかったこと｜X通常ポストの下書き自動化

### 4-1. 制約は3つ重なっている

| 制約 | 内容 |
|---|---|
| ① 公式APIに無い | 通常ポストの投稿API（`POST /2/tweets`）は呼んだ瞬間に公開される。下書き状態を作る引数が無い。下書きAPIがあるのはX記事（`/2/articles/draft`）と、広告用の別サービス（Ads API `draft_tweets`）だけ |
| ② MCPもAPIをなぞるだけ | 公式のX MCP（xmcp）はX APIをそのままMCPの道具に変換したもの。①でAPIに無い機能はMCP側にも存在しないはず |
| ③ Xの「下書き」自体が端末ローカル保存 | Xアプリ・Web版の「下書き（Unsent Posts）」は、保存した端末・ブラウザだけに残り、**アカウントには同期されない**。仮にブラウザを自動操作して保存できても、普段あなたが見ている下書き欄には出てこない可能性が高い |

### 4-2. 現実的な選択肢（優先順）

| # | 方式 | 自動化度 | リスク |
|---|---|---|---|
| 1 | 本文をファイルに保存 → 手でXに貼って下書き保存 or 投稿 | 低（執筆までは自動） | なし |
| 2 | 普段使うブラウザを自動操作し、下書きボタンまで押す | 中 | 規約上の自動操作リスク／ログインセッションを渡す必要／壊れやすい |
| 3 | 確認を挟んで `POST /2/tweets` を叩き、その場で即時公開する | 高（投稿までは自動、公開はワンクリック承認） | 誤投稿は取り消せない。「下書き」ではなく「確認後即投稿」になる |

## 5. 今どうしているか（暫定の代替運用）

上記1の方式を、今日から動く形にして用意した。

- ファイル：`post_to_file_貼り付け文.md`
- 中身：通常ポスト専用のスキル（x_post_workflow）を新設する指示文。X記事と同じくファクト検証はするが、投稿はせず `outputs/x_posts/` にファイル保存して止まる
- 使い方：手元のClaude Codeに貼るだけ。保存後は、あなたが手でXアプリに貼って下書き保存か投稿をする

これは「全自動」ではなく「執筆は自動、投稿の一手だけ手作業」という位置づけ。ほしのさんの運用と揃える前の、繋ぎの案。
